# Order Execution Risk Classification: Synthetic Data

This task predicts whether execution slippage will exceed a specified threshold using the order book at order submission, order information, and volatility. Each row is an independently generated simulated trading scenario with 20 input variables. The model should output the probability that `high_slippage=1`.

The order book and market changes before execution are generated by the assignment's stochastic mechanism. They have the basic structure of order-book trading, but they are neither quotes for actual securities nor the output of an execution model calibrated against real markets.

## Files and Fields

`train.csv` contains 5,000 labeled samples. Each order-book level has four columns, with level `j` taking values 1, 2, 3, and 4.

| Field template | Role | Description and units |
|---|---|---|
| `sample_id` | Identifier | A unique identifier generated for this assignment; must not be used as an input |
| `bid_price_j` | 4 inputs | Bid price at level j at order submission, simulated currency units/share |
| `bid_size_j` | 4 inputs | Quantity available on the bid side at level j at order submission, shares |
| `ask_price_j` | 4 inputs | Ask price at level j at order submission, simulated currency units/share |
| `ask_size_j` | 4 inputs | Quantity available on the ask side at level j at order submission, shares |
| `order_size` | Input | Quantity of the submitted order, shares |
| `side` | Input | Direction of the submitted order: `1` for buy, `-1` for sell |
| `latency_ms` | Input | Specified delay from order submission to execution, milliseconds |
| `volatility_bps_sqrt_s` | Input | Scale of recent price fluctuations, basis points/√second; not a percentage |
| `high_slippage` | Classification target | 1 if execution slippage exceeds 5 basis points (0.05%); 0 otherwise |

The 16 order-book input columns are ordered by level:

```text
bid_price_1, bid_size_1, ask_price_1, ask_size_1
bid_price_2, bid_size_2, ask_price_2, ask_size_2
bid_price_3, bid_size_3, ask_price_3, ask_size_3
bid_price_4, bid_size_4, ask_price_4, ask_size_4
```

Level 1 contains the best quotes: bid prices decrease and ask prices increase as the level number increases. A buy order consumes quantity on the ask side; a sell order consumes quantity on the bid side. Distinguish the bid and ask sides of the book from the direction of the submitted order.

`cv_folds.csv` contains `sample_id` and `fold`, where `fold` ranges from 0 to 4 and must not be used as an input. `metadata.json` provides the feature and target column names.

## Slippage and the Target

This assignment uses the **best executable quote at order submission** as its reference: `ask_price_1` for a buy order and `bid_price_1` for a sell order. Let `VWAP` be the volume-weighted average price of the simulated execution and `P_ref` the reference price. Then:

```text
slippage_bps = 10000 × side × (VWAP - P_ref) / P_ref
```

One basis point (bp) is 0.01%, or 0.0001 as a proportion. Adjusting for order direction makes adverse price changes correspond to positive slippage: buying at a higher price or selling at a lower price increases slippage. This definition excludes commissions and other fees. Its reference is not the mid-price at order submission.

The target is generated from subsequent random changes in prices and liquidity and the resulting simulated execution. Future changes and realized execution prices are not provided as inputs, so identical or similar current order books need not produce the same class. Do not interpret the target as a deterministic rule based only on the current static four-level order book.

## Preprocessing Notes

- No missing values have been artificially introduced. `side=-1` is a valid category code, not a missing value.
- Price levels and order quantities have different numerical scales. Available quantities and submitted order sizes may have skewed distributions.
- The mid-price at order submission can be calculated as `(bid_price_1 + ask_price_1) / 2`. Define the meaning and units of any relative-price, spread, or liquidity features you construct.
- Both `latency_ms` and `volatility_bps_sqrt_s` are available at prediction time. Future random market changes are not available information.
- The simulated currency unit does not correspond to a specific real currency. Results must not be interpreted directly as achievable execution performance in real markets.
